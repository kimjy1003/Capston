# 연구 개선 — 수익률 타깃과 방향 정확도

상위 폴더(`2026-09/`) 재작성본의 후속 분석이다(2026-09-29). 재작성본의 결론과 원본 수정 내역은
[상위 README](../README.md)에 있다.

가격 수준 회귀는 구조적으로 persistence(직전 값)로 수렴하므로, 타깃을 **3분 뒤 로그수익률**로 바꾸고
"얼마나 정확한가" 대신 **"방향을 맞히는가"**를 봤다. 전체 표는 [`results/direction_table.md`](results/direction_table.md).

## 설정

- 타깃 2개: `middle` 수익률(원 논문과 같은 가격)과 `close` 수익률(실제로 거래할 수 있는 가격).
- 입력: 원래 8개 컬럼을 정상성 있는 10개 피처로 바꿨다(수익률, 봉 폭, 봉 안 종가 위치, 이동평균 괴리,
  로그 거래량 등). 가격 수준을 그대로 넣으면 MinMax의 분포 이동 문제가 입력 쪽에서 다시 생긴다.
  StandardScaler는 학습(fit) 구간에만 fit한다.
- 모델: Ridge(최근 12스텝, alpha는 검증셋으로 선택), LSTM·GRU(상위 폴더 노트북과 같은 hidden 4 / 1층 /
  seq 288 / 조기 종료). 신경망은 시드 5개를 돌려 예측 평균(앙상블)을 대표값으로 쓰고 시드별 흔들림도 함께 적었다.
- 테스트 표본은 가격 수준 분석과 **같은 3,743개**다. 타깃·기준 시점이 일치하고 naive MAE도 38,595.65원으로 같아,
  가격 MAE를 [가격 수준 최종 표](../results/final_table.md)와 직접 비교할 수 있다.
- 방향 정확도는 수익률이 정확히 0인 표본(middle 2.0%, close 3.4%)을 뺀다. 비교 기준은 50%가 아니라
  단순 규칙 기준선(항상 다수 방향, 직전 방향 유지/반대, 봉 안 위치 `sign(close-middle)`)이고,
  차이의 유의성은 같은 표본에서 McNemar 정확 검정으로 본다. "최강 규칙"은 학습 구간 정확도로 고른다.

## 결과

| | middle 타깃 | close 타깃 |
| --- | --- | --- |
| 항상 다수 방향 | 50.1% | 51.6% (항상 하락) |
| 규칙: 직전 방향 유지 | 63.1% | 52.9% |
| 규칙: 봉 안 위치 `sign(close-middle)` | **72.5%** | 49.7% |
| Ridge (선형) | 73.0% | 50.1% |
| LSTM 앙상블 (시드별 평균 ± 표준편차) | 73.4% (73.2 ± 0.3) | 52.3% (51.7 ± 0.9) |
| GRU 앙상블 (시드별 평균 ± 표준편차) | 73.5% (73.0 ± 0.1) | 52.4% (51.7 ± 1.2) |
| LSTM 가격 MAE / naive | **0.796** | 1.003 |
| LSTM 신호로 close 매매, 수수료 후 | −58.2% | −41.5% |

**1. middle 방향 72%는 규칙 하나로 나온다.** `middle=(high+low)/2`는 봉 안의 평균 같은 값이라
수익률의 lag-1 자기상관이 +0.30이다(close는 −0.09). 봉이 middle보다 위에서 끝나면 다음 봉 middle이
오를 가능성이 높아서, `sign(close-middle)` 한 줄이 방향을 72.5% 맞힌다(학습 구간 71.6%로 안정적).
신경망은 여기에 +0.9%p를 더했을 뿐이고(McNemar p=0.013 / 0.003), Ridge는 규칙과 구분되지 않는다(p=0.19).

**2. 이전 결론의 수정.** 수익률 타깃에서는 선형 Ridge도 가격 MAE / naive 0.810으로 LSTM RevIN(0.845)보다 낫다.
가격 수준 표에서 RevIN이 naive를 이긴 몫은 이 기계적 예측 가능성으로 설명된다. "MinMax는 추세가 있는
가격에 구조적으로 쓸 수 없다"는 결론은 그대로이고, 타깃을 수익률로 바꾸면 RevIN이 풀던 분포 이동 문제 자체가
대부분 사라진다.

**3. 거래할 수 있는 가격(close)에서는 방향을 맞히지 못한다.** LSTM·GRU 52.3% / 52.4%는 "항상 하락"(51.6%)과
통계적으로 구분되지 않는다(McNemar p=0.60 / 0.55). 시드 하나만 보면 49.6~52.7%로 흔들린다.
middle에서 72%였던 봉 안 위치 규칙은 close에서 49.7%다. 학습 구간에서 가장 좋았던 규칙(직전 방향 반대, 50.4%)이
테스트에서는 47.0%로 뒤집혀, 방향 신호 자체가 기간마다 안정적이지 않다. 회귀로 봐도 수익률 0 예측
(= persistence)을 이기지 못한다(MAE 1.003~1.005배). MSE 회귀의 부호는 학습 구간의 평균(상승 추세)을 따라가서,
테스트가 하락 우세인데도 모델은 상승을 62~68% 찍었다.

**4. 약한 순위 신호는 있지만 거래로는 쓸 수 없다.** close 예측과 실제 수익률의 순위상관(IC)은
+0.09(p≈1e-8)로 유의하다. 단순 반전·봉 안 위치 신호를 제거해도 +0.07이 남아 출처는 아직 모른다
(반전은 큰 움직임 뒤에만 나타난다: 피어슨 자기상관 −0.085, 순위 기준 약 0).
그러나 3분 close 수익률의 평균 크기는 5.4bp이고 Upbit 왕복 수수료는 10bp라서, 매 봉 판단하는 전략은
방향을 전부 맞혀도 비용을 넘지 못한다. 실제로 수수료 전 +16~18%(같은 기간 단순 보유 +8.9%)가
수수료 후 −37~−41%가 된다. 수수료 전 수익도 호가 스프레드를 무시한 값이고 테스트 기간이 약 8일 한 번뿐이라
근거로 삼을 수 없다.

**정리:** 방향 정확도로 보면, 3분 뒤 BTC 방향은 거래할 수 있는 가격 기준으로 단순 기준선과 구분되지 않는다.
원 논문의 높은 정확도는 (1) 테스트셋 스케일러 유출, (2) 기준선 부재, (3) 거래할 수 없는 `middle` 타깃의
기계적 예측 가능성에서 나왔다.

## 재현

경로를 파일 위치 기준으로 잡아 두어 어느 폴더에서 실행해도 된다. 공통 모듈(`common.py`)과 데이터는
상위 폴더의 것을 그대로 쓴다.
```
python direction_experiment.py           # 타깃 2 × 모델 3, 시드 5개. RTX 3060에서 약 12분
python direction_experiment.py --quick   # 동작 확인용 (시드 1개, 3 epoch)
```
시드를 고정해 두어 다시 돌려도 같은 수치가 나온다. 표를 재학습 없이 다시 만들 수 있도록 테스트 예측을
`results/direction_predictions_*.npz`에 남긴다(커밋하지 않음).

환경: conda `capston` 환경 — Python 3.11, torch 2.6.0+cu124, scikit-learn, scipy, pandas 2.x, numpy 1.x.

## 구조

- `returns_common.py` — 정상성 피처, 규칙 기준선, 방향 정확도·McNemar 검정, 매매 평가.
- `direction_experiment.py` — 실험 실행과 표 생성.

## 남은 일

- close의 약한 순위 신호(IC +0.09)가 다른 기간에도 유지되는지. 지금 테스트는 약 8일 한 번뿐이다.
  여러 달 데이터를 받아 기간을 밀어 가며 재학습·평가(워크포워드)해야 우연인지 가릴 수 있다.
- 수수료를 넘는 움직임에서 다시 볼 것. 3분 수익률 평균 5.4bp는 왕복 수수료 10bp보다 작다.
  예측 거리를 늘리거나(15분·1시간), 예측 크기가 임계값을 넘을 때만 거래하는 방식으로 평가해야 의미가 있다.
- 방향을 직접 학습하는 분류 손실(BCE). MSE 회귀의 부호는 평균을 따라가서 close 모델이 상승 쪽으로 치우쳤다.
